# 展板露出核查

展板送印前，核对每幅原片在展板上**实际露出**的部分是否都落在其**可刊矩形**内。
全部合规时才可下载署名 CSV。

## 启动

```bash
docker compose up --build
# 打开 http://localhost:8000
```

本地开发（需 Python 3.11+）：

```bash
pip install -r requirements.txt
python app.py            # http://localhost:8000
python test_geometry.py  # 核查逻辑测试
python test_merge.py     # 合稿逻辑测试
```

## 使用

1. 在首页上传描述 JSON（可下载页面上的示例对照格式）。
2. 结果页按原片列出：**露出面积**、**缺许可面积**；有缺口时给出**一处未获许可的原片坐标**。
3. 整页无缺口时出现「下载署名 CSV」按钮，CSV 只列实际露出的原片编号与署名。

## 合稿

两位排版员各自改了同一份展板时，可在首页进入**合稿**，上传底稿与两份修改稿，
把改动合成一份可送印的稿件：

1. 三稿都使用下述 JSON 格式，但每片裁片必须带唯一 `id`，
   同一裁片在三稿中沿用同一个 `id`。
2. 展板尺寸、原片清单、裁片编号集合、各裁片所用的原片必须一致，否则无法合稿。
3. 合并规则：
   - `crop`（裁框）与 `at`（落版位置）按裁片编号逐字段三方合并：
     只有一方改动、或两方改得一样就采用；两方都改且新值不同，
     结果页会指出裁片编号与字段，需协商后重新合稿。
   - 层序：任意两片，只要有一稿调换了上下关系就按调换后的顺序，
     两稿都没调换就保留底稿顺序；若这些关系成环，会指出环上的裁片编号。
4. 合稿成功后自动重新核对刊用范围（沿用核查页的缺口提示）；
   只有无冲突且无缺许可时才可下载合稿 JSON。文件保留裁片编号，
   可直接上传到原核查页。

层序合并不建立两两关系矩阵，只保存位置表与入度数组等线性结构，
**额外内存随裁片数线性增长**（O(n)），时间 O(n²)。

## JSON 格式

```json
{
  "board": {"width": 6000, "height": 4000},
  "photos": [
    {"id": "A-001", "credit": "陈晨",
     "permit": {"x": 0, "y": 0, "w": 2400, "h": 1600}}
  ],
  "pieces": [
    {"id": "P-01",
     "photo": "A-001",
     "crop": {"x": 100, "y": 80, "w": 1200, "h": 900},
     "at": {"x": 300, "y": 250}}
  ]
}
```

- `board`：展板尺寸，整数像素，宽高可达 100000。
- `photos`：原片清单。`permit` 为可刊矩形（原片坐标）。
- `pieces`：裁片，**从下往上**排列（数组越靠后层级越高）。`crop` 为原片裁框
  （原片坐标），`at` 为落版位置（裁框左上角在展板上的坐标）。
  `id` 为裁片编号：核查时可选，合稿时必需。
- 所有坐标为整数像素；矩形宽高的字段名 `w`/`h` 或 `width`/`height` 均可。
- 坐标系：原点左上，x 向右，y 向下；裁片按原尺寸铺放、互不透明。

## 计算规则

- 每片裁片的可见部分 = 其落版矩形（裁剪到展板内）减去所有更上层裁片的矩形。
- 可见部分平移回**原片坐标**后，同一原片多处的重叠区域只计一次（矩形并集）。
- 露出面积 = 并集面积；缺许可面积 = 并集中落在可刊矩形外的部分。

## 内存说明

核查全程只操作矩形列表（矩形差集 + 扫描线求并集面积），**不建立像素画布**，
内存占用只随裁片数量增长，与展板像素尺寸无关——十万像素见方的展板同样适用。
